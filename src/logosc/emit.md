# `src/logosc/emit.logos` — the emitter

The port of `logos/llvm.py`. `emit` takes the arena `ir.logos` built and returns
the module's LLVM IR text, one `.ll` file's worth, trailing newline included.
The text is the interface to clang and to the wave's gate, which compares it byte
for byte with Python's, so every spelling rule below is a copy of `llvm.py`, not
an interpretation of it. Read `ir.md` first for the vectors' meanings.

Logos has no comments, so this file is the documentation the source cannot carry.

## API

```logos
(fn emit ir-error ((mtriple …) (mqual …) (tags names elem extra powner)
                  (snames sbase scount sftys) (enames ewords)
                  (gnames gdata) (dnames dsig dcnt dret sigtys)
                  (fnames fsyms fint fret fbase fcnt fparam fpc)
                  (pnames ptys)
                  (blabels bbase bcnt bterm bty bhas bv1 bv2 bv3)
                  (ops dests a b c d t1 t2 t3 n1 sst scn tst tcn svals tvals)
                  (out (ref (vec :str)))))
(fn emit-type-text :str ((tags names elem extra powner enames ewords mqual)
                         (ty :i64) (why (ref (vec :str)))))
```

Twelve parameter groups, 56 parameters, every one the caller's vector: the
emitter holds no state, frees nothing it did not allocate, and two calls cannot
see each other. `out` receives the text (replacing its one entry if it has one),
and the return value says whether the text means anything.

`emit-type-text` is the same spelling for one type id, with a fresh internal
table; the parity suite uses it to pin all fifteen type constructors one at a
time.

### Failure

Python raises `ValueError`; this returns `ir-error` and writes `text`. The
message names the same fact in the same words where the words are the contract:

| Python | here |
|---|---|
| `unknown IR opcode '…'` | `unknown IR opcode N` (the vocabulary is numeric) |
| `call to undefined function '@x'` | same |
| `'x' takes N arguments, call passes M` | same |
| `address of undefined function '@x'` | same |
| `reference to undeclared global '@x'` | same |
| `indirect call passes N arguments for M` | same |
| `block 'x' has no terminator` | same |
| `unknown IR terminator '…'` | `unknown IR terminator N` |
| `no layout registered for enum 'x'` | same |
| `no LLVM layout for type …` | `no LLVM layout for type <name>` for a type variable (tag 14), `:name` for a primitive, `type tag N` for any other tag |

The first failure wins: `flag[0]` is set once and `why[0]` keeps its message, so
a row that fails several ways still reports the first. A failed emission returns
an empty `out`; callers must check `ir-good` before reading it, and the suite's
negative cases do.

### Malformed arenas

Every type id is bounds-checked before it is read, so an arena built by hand —
or by a lowering bug — is refused with an `ir-error` instead of aborting in
`vec-get`:

| malformed | message |
|---|---|
| a type whose child id is not older | `type N has a child id that is not older` |
| a row's `t1` or `t2` outside the arena | `IR row N reads a type id the arena does not have` |
| a row that needs a type but has `-1` | `IR row N has no type` |
| a `ret` that carries a value but has `bty = -1` | `block 'x' terminator has no type` |
| a type id in a run (`sigtys`, `ptys`, `tvals`, `dret`, `fret`) | `type run entry N reads type id M` |
| a terminator's `bty` outside the arena | `block 'x' terminator reads a type id the arena does not have` |

The forward pass's assumption is part of the contract: a type's children must
have **older ids** — the constructors append children first and
`type-substitute` rebuilds in the same order. `emit-types` checks that before it
spells anything, and `emit-instr`/`emit-term` check the slots that name a type.
`-1` is the arena's "no type"; it is accepted only where the opcode does not
read the slot, so `alloca` with `t1 = -1` is refused rather than printing
`  %z = alloca ` with a trailing space. An index into `svals` or `tvals` (a
row's `sst`/`scn`/`tst`/`tcn`, a block's `bbase`/`bcnt`) remains the producer's
invariant: the typed constructors are the only guard there.

## The module's shape

Python joins a list of lines; this joins a vector of lines. The order is fixed:

1. `; generated by logos`
2. `target triple = "<triple>"`
3. a blank line
4. one `%struct.X = type { … }` per struct, in declaration order
5. a blank line if there were structs
6. one `@name = private unnamed_addr constant …` per global, in the order given
7. a blank line if there were globals
8. one `declare …` per declaration, in the order given
9. a blank line if there were declarations
10. each function, a blank line **between** functions but none before the first
11. a final newline

Enums produce no line at all: an enum's width is only ever read while spelling a
type, exactly as in `llvm.py`. Structs are never sorted or grouped — the order
is the field list's order, and that order is what gives the aggregate C layout.

The join is a balanced tree (`emit-join` splits the line vector in half), not a
left fold: `str-concat` copies both arguments, so folding a module's lines would
be quadratic in its size. The wave's gate emits the compiler's own source, where
that difference is the difference between seconds and minutes.

## Types

`emit-types` spells every type in the arena once, into a vector indexed by type
id, before a single instruction is printed. A type's children must have older
ids — the constructors append children first, and `type-substitute` rebuilds in
the same order — so one forward pass is enough and each spelling is O(1)
afterwards. `emit-types` checks that invariant and refuses a type whose child is
not older (`Malformed arenas` above), so the sweep is a validated pass rather
than an assumption. `emit-text texts ty` is that lookup, and `-1` reads as `""`
(the arena's "no type", which only an opcode that does not read that slot leaves
behind).

| tag | constructor | spelling |
|---|---|---|
| 0 | primitive | the table below |
| 1, 2 | `ptr`, `own` | `T*` |
| 3 | `arr` | `[n x T]` |
| 4 | `vec` | `{ T*, i64, i64 }` |
| 5 | `ref` | `T*` (the pointer to the vector descriptor) |
| 6 | `res` | `{ i1, T, E }` |
| 7 | `opt` | `{ i1, T }` |
| 8 | `fn` | `{ i8*, i8* }` |
| 9 | `shared` | `T` — a marker, not a layout |
| 10, 11 | `chan`, `atomic` | `i8*` — opaque runtime handles |
| 12 | `struct` | `%struct.<decl-name>` |
| 13 | `enum` | `{ i32, [K x i64] }`, `K` from the module's enum list |
| 14 | `var` | refused: `no LLVM layout for type <name>` |

Primitives: `i8 i16 i32 i64` as themselves; `u8 u16 u32 u64` on the same widths;
`bool` as `i1`; `f32` as `float`; `f64` as `double`; `str` as `{ i8*, i64 }`;
`void`; and `thread`, `mutex` and `run` as `i8*`. Any other name is refused:
`no LLVM layout for type :nope`, as Python's `ValueError` does, so a primitive
spelled outside the closed list fails loudly instead of becoming a pointer.

**Typed pointers, never `ptr`.** `llvm.py`'s docstring is the reason: clang 14
parses `ptr` only under `-opaque-pointers`, so the emitter spells `i8*` at the C
boundary and `[N x i8]*` for a string global. Every `T*` above descends through
the element type, so a `(ptr point)` is `%struct.point*`, not `i8*`, and a
`(vec :i64)` is `{ i64*, i64, i64 }`.

`emit-record` spells a literal struct — a closure environment or a `Vec`'s
descriptor — as `{ T, T }`, or `{ }` when it has no fields. `emit-fnptr` spells a
callable's real type, `R (P1, P2)*`, from the parameter run.

### Named types and quoting

A struct or enum is spelled by the name the producer stored: `emit-decl-name`
returns `names[ty]`, and `emit-struct-line` prints `snames[i]`. Python's arena
works the same way — `lower.Symbols.type_name` qualifies a named type once, when
it is lowered, and `IrStruct.name` / `StructRef.name` then carry the final
spelling — so one module stores `point` and a unit of several stores
`shapes.point`, and the definition line and every use are the same string by
construction.

`mqual` and `powner` stay in the signature because they are fields of the
arena, but the spelling pass does not read them: a non-empty owner beside an
already-qualified name is provenance, not a prefix to add a second time. The
`multi-module` parity case builds exactly that arena (final names, owners
recorded, `mqual = 1`) and requires the definition and the use to agree.

`emit-name` adds a sigil and quotes when LLVM's unquoted grammar does not accept
the name: `[-a-zA-Z$._][-a-zA-Z$._0-9]*`, matched byte-wise against ASCII. A name
that fails is printed `@"…"`, with every byte outside printable ASCII — and every
`"` and `\` — escaped as `\XX` in uppercase hex. So `lg.m.odd name` prints as
`@"lg.m.odd name"`, `struct.odd name` as `%"struct.odd name"`, and a parameter
`v 0` as `%"v 0"`.

Two places are deliberately **not** quoted, because `llvm.py` does not quote
them: a block label (`entry:`, `br label %join`) and a global's definition line
(`@.str0 = …`). Labels and global names the lowerer produces are in LLVM's
grammar; the operand spelling of the same global *is* quoted. Copying the
omission keeps byte equality, and `emit.md` is where the asymmetry is recorded.

## Globals

A string global is an array of exactly its own bytes — no NUL terminator,
because a Logos string carries its length. The init is a `c"…"` literal with the
same `\XX` escaping as a quoted name, so a quote, a backslash, a newline and a
NUL all round-trip:

```llvm
@.str0 = private unnamed_addr constant [15 x i8] c"he said \22hi\22\5C\0A\00"
```

An empty global is `[0 x i8] zeroinitializer`. `gaddr` looks the name up to get
the length for both the array type and the operand, and reports
`reference to undeclared global '@x'` when it is absent.

## Functions and calls

A function is `define ` + `internal ` (when `fint`) + return type + symbol +
`(params) {`, where the symbol is `fsyms[f]` when it is non-empty and the source
name otherwise — `main` keeps its name and external linkage, a program function
has already been mangled to `lg.<module>.<name>` by the lowerer. A parameter is
`T %name`, its name quoted if need be.

A call looks its callee up by **symbol** among declarations first, then among
functions, and prints the arguments with the *signature's* types — the callee
name is a key, not a type. An unresolved callee and an arity mismatch are the two
failures above; a declaration's signature lives in `sigtys[dsig …]`, a
function's in `ptys[fparam …]`. `dest` empty prints `call …` with no `%x = `
prefix, which is how a `void` call is spelled.

`faddr` needs the same signature: it prints
`%x = bitcast R (P…)* @symbol to i8*`. `fnptr` prints the reverse cast with the
parameter run stored on the row (not looked up), and `icall` prints
`call R %callee(args)` with the row's parameter types and `dest` prefix rule
shared with the direct call.

`ret` prints `ret void` when `bhas = 0` and `ret T value` otherwise. `br` and
`cbr` print labels bare, `cbr` as `br i1 cond, label %a, label %b`.

## The parity harness

There is no lowerer in PR A, so `emit` is tested by construction.
`tools/ir_parity.py` holds fifteen modules as `logos.ir` values, emits each with
`logos.llvm.emit`, and writes it to `src/logosc/fixtures/ir/<name>.ll` under a
two-line provenance header. It also writes the same module as a sequence of
`ir.logos` constructor calls into `src/logosc/emit_test.logos`, which builds it,
emits it, and compares the text with the file, byte for byte, at `-O0` and `-O2`.
The comparison reports the first differing byte, its line number, and both
lines, so a one-character drift is readable without a diff tool.

The modules cover: the empty module; a `:void` function that returns; an `:i64`
function with `add`, `icmp`, a branch and a `phi`; a struct by value through
`alloca`/`store`/`load` and a `gep` into it; an array; a string global with a
quote, a backslash, a newline and a NUL; a call to an `extern`; a global constant
counter read by two functions; a name LLVM needs quoted; an enum through
`insertvalue`/`extractvalue`/`gep`; a two-module unit whose struct and enum are
spelled `shapes.point` and `colors.tone`; a closure environment through
`allocarec`, `geprec`, `bitcastrec` and `bitcastout`, and a call through
`fnptr`/`faddr`/`icall`; every integer, float and cast row; and `unreachable`.
Between them the cases exercise all 43 opcodes, which the generator checks
before writing anything: a printer branch no case reaches is a build failure,
not an untested line.

`type-text` is the fifteenth-constructor row: fourteen spellings, one per type
constructor that has a layout, compared with `type_text` of the same
`logos.types` values. The fifteenth, a type variable, has no layout; its refusal
is a negative case, and the generator takes the expected text from the exception
`type_text` raises (`no LLVM layout for type T`), so the port must reproduce
Python's words rather than its own. The other negative cases pin a mis-shaped
row (`unknown IR opcode 0`), a primitive outside the list, an unterminated block,
an unregistered enum, a dangling row type id, an out-of-order type child and a
row with an unset type slot. The last three are **port-only**: no Python
`IrModule` reaches those checks, so their fixtures carry a third header line
saying that the expected message is the port's. The generator also proves the
reference still refuses an unknown opcode and still refuses to spell a type
variable, so the port's refusals cannot drift from Python's silently.

Regenerate with:

```text
python3 tools/ir_parity.py
python3 -m logos test src/logosc/emit_test.logos --opt -O0 --opt -O2
```

The generated test reads its fixtures by repository-relative path, so run it
from the repository root, as every suite here is run. Adding a case is one entry
in `MODULES`: the fixture, the constructor sequence and the expectation all come
from it. The generator formats the test file with `python3 -m logos fmt`, so the
output is a fixed point of the formatter.

## Build set

`src/logosc/emit.logos` imports `ir` (`(use ir)`); `src/logosc/ir.logos`
imports nothing. Both are part of `src/logosc/*.logos`, so `gen2` and the
self-hosting gate build them with the rest of the front end.
`src/logosc/emit_test.logos` is a module whose `(test …)` forms are run by the
suite and never by `gen2`'s `main`; its fixtures live under
`src/logosc/fixtures/ir/` and are not part of the manifest, which lists
`*.logos` files only.
