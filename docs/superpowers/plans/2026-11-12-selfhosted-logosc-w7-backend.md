# W7 — the backend, in Logos, in three pull requests

Wave W7 of `docs/superpowers/specs/2026-11-08-self-hosted-logosc-design.md`. This is the wave that
turns a checked tree into LLVM IR text, and its gate is the one the whole project is measured
against: `gen2 build` must produce the same `.ll` as Python on every positive corpus file.

Read with `logos/lower.py` (4,997 lines) as the specification, `logos/ir.py` (170) for the opcode
vocabulary, `logos/llvm.py` (572) for the spelling, and `src/logosc/check.logos` for the shape a
port of a big pass takes. The wave is three pull requests because one is not reviewable.

## PR A — the IR arena and the emitter

`src/logosc/ir.logos` + `ir.md`, `src/logosc/emit.logos` + `emit.md`.

- **IR as arenas, not tuples.** Python's instruction is a tuple whose item 0 is the opcode and
  whose operands are values and types. In Logos a record is a handful of parallel vectors: the
  opcode, the destination, up to four operand slots, and a type id — one row per instruction, with
  a function/block index so a block is a slice. The vocabulary is closed and copied from `ir.py`;
  an opcode the emitter does not know must fail loudly, as Python's does.
- **The emitter.** `emit` is one function per module: the triple, the named struct rows, the
  globals, the function signatures, then each block's instructions and its terminator. Copy the
  spelling rules from `llvm.py` verbatim, including the traps its docstring names: typed pointers
  (`i8*`, `[N x i8]*`, never `ptr`), string globals as exactly their bytes with `\XX` escapes, a
  mangled symbol when one exists, quoted identifiers for names LLVM will not read unquoted, and
  identified structs in declaration order so the layout is C's.
- **Parity without a lowerer.** The port has no lowering yet, so `emit` is tested by construction:
  `src/logosc/emit_test.logos` builds each module through the port's own constructors and compares
  its text with a committed expected file. The expected files are generated by
  `tools/ir_parity.py`, which builds the same module in Python and calls `logos.llvm.emit` — and,
  like `tools/types_parity.py`, it must fail the build if Python refuses a module rather than
  writing a row the port happens to match.
- **Coverage.** At least: an empty module; a `:void` function that returns; an `:i64` function with
  `add`, `icmp`, a branch and a `phi`; a struct by value through `alloca`/`store`/`load`; an array;
  a string global with a quote, a backslash and a newline; a call to an `extern`; a global constant
  counter across two functions; and a name LLVM requires quoted.

## PR B — lowering: declarations, expressions, control flow

`src/logosc/lower.logos` + `lower.md`, and the `build` verb behind it.

- Every declaration Python lowers: functions and their signatures, locals and their allocas,
  structs and enums, globals, externs.
- Every expression form: arithmetic and the integer widths, comparisons, casts, the short-circuit
  `and`, string and vector literals, field access, indexing.
- Control flow: `if`/`else` with `phi`, `while`, `match` over an enum's tag, `ret`, blocks and their
  terminators.
- The parity harness of this PR is **text on a subset**: `gen2 build --emit` on the positive corpus
  files whose forms this PR lowers, diffed against Python's `.ll`. The file list lives in
  `tools/selfhost-ir.txt` and is floor-guarded, exactly as the check list is.

## PR C — lowering: ownership, calls, containers, concurrency, and the gate

- The rest of `lower.py`: calls (direct, indirect, `extern`), `spawn`/`join`, channels, mutexes and
  atomics, results and optionals, closures and their captured environments, `alloc`/`free`,
  `vec-*`/`arr-*`/`str-*`, `print`/`println`, and the lowering of moves and drops.
- `tools/selfhost-ir.txt` grows to every positive corpus source, then to the compiler's own
  `src/**/*.logos`. `tools/selfhost.sh` gains the phase: build `gen2`, then for each file compare
  `gen2 build`'s `.ll` with Python's, byte for byte.
- **PR C is done when `gen2 build` and Python agree byte for byte on the whole list**, and the
  binaries built by each behave the same at `-O0` and `-O2` on the exec corpus.

## Review focus

1. **Byte equality, not clang acceptance.** Two `.ll` files that both compile are not equal, and
   the gate compares text. A difference in constant naming, in block order, in a `phi`'s incoming
   order or in a struct row's position fails it.
2. **The IR arena must not invent a second opcode vocabulary.** If `emit` accepts an opcode
   `lower.py` cannot produce, or `lower.logos` produces one `emit` cannot print, the port can pass
   its own tests while diverging on the corpus.
3. **Types are the emitter's input, so a wrong `type_text` shows up as wrong IR everywhere.** Pin
   all 15 type constructors, as `type-text` did in W6.
4. **A lowering that only works at `-O0` is a bug.** The gate runs both levels.
5. **Numbers.** Module growth, memory, and the time to lower the compiler's own source: a port
   that is quadratic in a function's instruction count passes but cannot build itself.
